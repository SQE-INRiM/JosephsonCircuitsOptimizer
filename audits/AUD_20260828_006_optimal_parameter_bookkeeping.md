# AUD_20260828_006 — Optimal parameter bookkeeping

Status: **qualified**

## Scope

Review and fix the mismatch between `optimal_device_parameters.json` and the fully evaluated device parameter set used by the circuit.

## Evidence

The validated `chalmers_3wm(4).jco` run showed that Optimization completed with nonzero optimized coordinates, while `optimal_device_parameters.json` still stored `Cj_small = 0` and `Ic_density = 0`. The same run's later bookkeeping contained the correct derived values after Harmonic Balance constructed the circuit.

The user circuit populates model-derived values by mutating the `device_params_set` dictionary passed to `create_user_circuit`. In the full run path, the optimal JSON was written immediately after Optimization, before the nonlinear stage called `create_circuit(optimal_params)`. Therefore explicit optimization coordinates were correct but derived fields had not yet been materialized at serialization time.

## Change

Added `runtime/bridge/gui_runtime_bookkeeping_fixes.jl`, loaded after the existing desktop runtime overrides. The three-argument `save_output_file` method now detects `optimal_device_parameters*.json`, deep-copies the parameter dictionary, calls `create_circuit` on that copy so `create_user_circuit` can populate derived fields, and serializes the completed copy.

This applies consistently to the main optimum, single-point optimum and nonlinear-correction optimum files. Other JSON outputs are serialized unchanged.

## Scientific-integrity assessment

- Optimizer bounds, objective values and returned optimized coordinates are unchanged.
- The original parameter dictionary passed by the caller is not mutated by the bookkeeping fix.
- The additional circuit construction is used only to materialize model-defined derived metadata before persistence.
- If materialization fails, the runtime warns and preserves the existing available values instead of aborting an otherwise valid simulation.

## Remaining validation

Julia execution is not available in the audit environment. A fresh GUI run should confirm that `optimal_device_parameters.json` now contains nonzero derived `Cj_small` and `Ic_density` values matching those generated by `create_user_circuit` and later recorded in run bookkeeping.
