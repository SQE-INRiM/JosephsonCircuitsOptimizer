# JosephsonCircuitsOptimizer v0.5.0

This release brings the nonlinear-feedback workflow into the integrated JCO desktop application and improves optimizer result selection and reproducibility. JCO remains a Julia package with an Electron GUI; Julia is still provided separately.

## Highlights

### Nonlinear feedback
- Run successive Linear → Optimization → Harmonic Balance cycles using a user-defined nonlinear correction, with either a fixed number of cycles or an optional convergence stopping criterion.
- Navigate completed cycles separately in Results, including the cycle-specific Linear, Optimization and HB outputs and the feedback evolution view.
- Reuse the nonlinear correction already computed at a matching HB point whenever possible, and reuse previously computed full linear solutions across feedback cycles (subject to a 2 GiB in-memory cache limit).
- The correction may appear anywhere inside `user_cost(sol, device_params_set, nonlinear_correction)`; cached solutions do not bypass recalculation of the user cost and saved metrics.

### Optimizer
- Normalize surrogate inputs internally while retaining physical device parameter values in simulation results and saved output files.
- Record feasibility separately and avoid feeding the large legacy mask penalty directly to Kriging + SRBF; this is a training-only proxy, not a general constrained optimization method.
- Honor the configured random seed when constructing and sampling the surrogate.
- Always choose the final design from *actually evaluated, feasible* initial-sweep or optimizer points. If Surrogates returns `nothing`, use the best feasible measured point with a warning. If none exists, report an error rather than accepting a masked configuration.
- Improve persistence of optimizer evaluation history for GUI and direct Julia workflows.

### GUI and results
- Show feedback-cycle status and navigation without changing the three familiar Linear, Optimization and HB stages.
- Maintain cycle-aware data, selected plots, and separate optimizer Landscape/History views.
- Preserve established project menu, Setup, Run, Results, and CSV export workflows from v0.4.3.

## Compatibility

- JCO Julia package and GUI: **0.5.0**.
- Existing `.jco` project containers and output formats remain supported; no new project archive schema is introduced.
- **User-function contract:** `user_nonlinear_correction(sol_linear, sol_nonlinear, device_params_set)` receives full JosephsonCircuits solutions. Older user functions expecting a linear S-parameter dictionary must be updated.
- Julia is an external runtime prerequisite; it is not bundled. Windows builds remain unsigned and Linux has received less end-user runtime validation.

## Known limitations

- Windows packages are unsigned; Windows SmartScreen or Smart App Control may require additional user attention. Julia is installed separately.
- Linux AppImage support remains preliminary and is distributed for x86-64.
- Numerical HB/reference-data validation of the nonlinear-feedback workflow is not fully independent. Automated regression tests and maintainer GUI testing cover a narrower scope.
- Legacy user-authored nonlinear-correction hooks that expect a reduced linear S-parameter dictionary must be adapted to accept the full linear `hbsolve` solution.
